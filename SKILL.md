# Paper Reader

For installation, see [README.md](README.md). Resolve scripts and assets relative to this skill directory, regardless of the working directory.

Read references once, only for the current phase: [html-content-spec.md](references/html-content-spec.md) for source HTML creation/repair; [translation-style.md](references/translation-style.md) and [glossary.tsv](references/glossary.tsv) for translation; the matching section of [workflow.md](references/workflow.md) or command `--help` for details. Execute scripts; do not read implementation or dump raw extraction/full articles unless diagnosing a specific failure.

Resume an existing reader's current phase. Accepted, unchanged English/PDF/assets need no repeated extraction, HTML search or source review. `translate` verifies fingerprints; never renew acceptance merely to bypass a mismatch. Inspect saved patches/QA scope; finish any emphasis patch interrupted after translation before fetching another batch.

1. Accept exactly one local PDF path, a directory containing one PDF (case-insensitive extension), a direct PDF URL, or arXiv URL/ID. Use `scripts/reader.py resolve INPUT` for local inputs; remote inputs go directly to `extract INPUT --output OUTPUT`. There is no required library layout, citekey, bibliography, or note. Local output defaults to `<PDF-stem>-reader/` beside the PDF; use `--output` to choose a different location. Never alter the original PDF or adjacent user files. Process one paper unless the user explicitly requests more.
2. Reuse Python/Docling/models. `extract INPUT` performs standard Docling parsing, collects emphasis and creates English HTML plus pending Chinese. PDF is authoritative; native parsing cannot establish academic structure. Search official arXiv HTML, accessible publisher HTML, then ar5iv; verify exact PDF version before `align-html`. Missing HTML never prevents conversion.
3. Reconcile every section, paragraph, caption, figure, table, equation, appendix and reference against PDF before acceptance/translation. Repair semantic English HTML, preserving order/emphasis; record corrections in `quality-report.json.source_review`. Tables always use complete original-PDF crops (translate captions only); crop unreliable math/figures. Keep related subfigures/left-right relationships together. Never redraw figures or derive equations.
4. Finish repairs, then `sync-source READER` (refuses translations/acceptance). `render READER`, inspect file:// and verify completeness, order, math, crops and references. Only then `accept-source READER --review-note "actual checks and limits"`. Fingerprinting does not perform semantic review.
5. `pending READER` defaults to compact output, at most 10 units and 8,000 JSON characters; optionally `--section ID`. One oversized unit is emitted intact with a warning. Translate only this batch. Preserve every `{{N}}` token; previews are context, never replacement markup. Inspect unclear/truncated/formula-dependent tokens with `pending READER --id UNIT --full`; explicit IDs also inspect translated units.
6. In the same reading pass, translate, check omissions/negation/uncertainty/conditions/quantities/terminology, and align emphasis by meaning only for units with source `styles`. Save an ID-to-string translation patch plus a separate emphasis patch under `source/translations/` (schema in workflow). Apply `translate READER PATCH`, then `format READER --patch EMPHASIS` if nonempty, before fetching the next batch. Existing translations/manual formatting are protected; `--replace ID` requires an explicit user replacement request. Python does not translate or need a paid API.
7. After batches, `render READER` then `check READER`. Let Python check structure, IDs, tokens, emphasis, assets, references and fingerprints; do not duplicate mechanical checks manually or rerender per batch. Actually inspect file:// language modes (headings/captions included), links, formulas, enlargement, mobile/desktop and dark mode. Revisit changed/unresolved passages, without automatically rereading all accepted source/reviewed translation. Record actual batch coverage/findings/limits in `quality-report.json.manual_reviews`; automatic checks prove neither PDF completeness nor semantic fidelity.
8. Fix content in HTML, display behavior in shared template/CSS/JS, never generated index.html or paper-specific CSS/scripts. Reading needs no server/fetch/network; renderer never translates, repairs source or guesses numbering. Shared display changes require regressions.

Legacy JSON: `migrate READER` once preserves JSON/translations and refuses HTML replacement. Check before rendering; missing full table crops require repair. Pure legacy rendering remains supported; never migrate/retranslate the whole library automatically.


Run `python scripts/reader.py --help`. Install dependencies from `requirements.txt` if no compatible environment exists. PDF/HTML operations use Docling, `lxml`, `pypdfium2` and Pillow; Poppler supports HTML comparison and PDF emphasis extraction. Translation is performed by the agent, not the Python script. The glossary starts empty; choose terms for this paper without assuming a particular reader background. Accept explicit Docling/model paths, without depending on one user's absolute paths.
