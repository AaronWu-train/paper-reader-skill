# Paper Reader

For installation, see [README.md](README.md). Resolve all scripts and assets relative to this skill directory, regardless of the working directory.

Read [html-content-spec.md](references/html-content-spec.md) before creating/editing content, [translation-style.md](references/translation-style.md) and [glossary.tsv](references/glossary.tsv) before translation. Read [workflow.md](references/workflow.md) for commands, reconciliation and validation.

1. Accept exactly one local PDF path, a directory containing one PDF (case-insensitive extension), a direct PDF URL, or arXiv URL/ID. Use `scripts/reader.py resolve INPUT` for local inputs; remote inputs go directly to `extract INPUT --output OUTPUT`. There is no required library layout, citekey, bibliography, or note. Local output defaults to `<PDF-stem>-reader/` beside the PDF; use `--output` to choose a different location. Never alter the original PDF or adjacent user files. Process one paper unless the user explicitly requests more.
2. Reuse compatible existing Python/Docling/models. `extract INPUT` performs standard Docling PDF parsing, collects available source emphasis, and creates `content.en.html` plus a pending `content.zh.html`. PDF is authoritative; native parsing does not establish academic structure. Never abandon a paper because HTML is unavailable.
3. When available, use official arXiv HTML, accessible publisher HTML, or ar5iv as an auxiliary source. Verify the exact version before `align-html`; any HTML reconciliation must precede source acceptance and translation. If no matching HTML is available, repair and review the extracted English directly against the PDF and continue without `align-html`. Check all sections, paragraphs, captions, figures, tables, equations, appendix and references against PDF; recover missing content and record corrections in `quality-report.json.source_review`.
4. Finish the English content first. Edit semantic HTML, not generated index.html. Preserve paragraph order and emphasis. Tables use full original-PDF crops in every mode; translate only captions. Use original-PDF crops for unreliable math/figures. Keep related subfigures together or retain the complete original crop when captions refer to left/right. Never redraw figures, derive equations or alter original PDFs/notes. After English repairs, `sync-source READER` rebuilds the untranslated Chinese scaffold; it refuses existing translations or an accepted source.
5. Run `render READER` to produce the English reader, inspect it in a file:// browser, and verify source completeness/order, mathematics, crops and references. Fix source errors before acceptance. Run `accept-source READER --review-note "actual checks and limits"` only after doing that review. This fingerprints English, PDF and assets; it is not an automatic certificate of semantic correctness.
6. `pending READER --section ID` emits untranslated prose, protected math/link tokens and source emphasis. Codex produces an ID-to-string JSON patch; `translate READER PATCH` writes Chinese HTML without changing English. Preserve every `{{N}}` token exactly. Then align Chinese emphasis by meaning using `format READER --patch PATCH`. Save batches and resume only pending units. Python does not translate and needs no paid API. Existing translations/manual formatting are protected; `--replace ID` is only for replacements explicitly requested by the user.
7. `render READER` composes both HTML contents with the same template/CSS/JS. Reading needs no server, fetch or network. Renderer never translates, repairs source or guesses numbering. Fix content errors in HTML; fix display behavior once in shared assets, with regression checks. Do not add paper-specific CSS or ad hoc display scripts.
8. `check READER` verifies bilingual structure, IDs, protected content, translations, emphasis, assets, references and PDF fingerprint. Actually check file:// modes (including headings/captions), links, formulas, image enlargement, mobile/desktop and dark mode. Compare translations for negation, uncertainty, conditions, quantities, terminology and omissions. Record real scope/findings/limits in `quality-report.json.manual_reviews`; automated checks do not prove PDF completeness or semantic fidelity.

For an existing JSON reader, use `migrate READER` once. This preserves the legacy JSON and existing translations, adds the two HTML contents and provenance sidecar, and never silently replaces existing HTML. Check before rendering; legacy readers without full table crops require source repair. Do not retranslate or migrate the entire library automatically. Pure legacy rendering remains supported until explicitly migrated.

Run `python scripts/reader.py --help`. Install dependencies from `requirements.txt` if no compatible environment exists. PDF/HTML operations use Docling, `lxml`, `pypdfium2` and Pillow; Poppler supports HTML comparison and PDF emphasis extraction. Translation is performed by the agent, not the Python script. The glossary starts empty; choose terms for this paper without assuming a particular reader background. Accept explicit Docling/model paths, without depending on one user's absolute paths.
